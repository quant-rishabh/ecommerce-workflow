2. Backend
This is where the interesting stuff happens.
For Next.js, you can initially have:

  api/

}

Backend
   ↓
LLM

You tell the LLM:

- getOrder
- getCustomer
- getShipment

The LLM looks at:
"Where is my order #10492?"

and decides:
I need getOrder.

Technically, the model returns something conceptually like:
{
  "tool": "getOrder",
  "arguments": {
    "orderId": "10492"
  }
}

3. Tool
This is the most important concept for you to understand.
You write normal TypeScript functions.
For example:
getOrder(orderId)

That function talks to Supabase.
Conceptually:
getOrder("10492")
        ↓
Supabase
        ↓
orders table
        ↓
{
  id: 10492,
  status: "OUT_FOR_DELIVERY",
  expectedDelivery: "Today"
}

Then your backend gives that result back to the LLM.
Now the LLM sees:
User:
Where is my order #10492?

Tool result:
Order 10492
Status: OUT_FOR_DELIVERY
Expected delivery: Today

And generates:
Your order #10492 is out for delivery and is expected to arrive today.

Backend sends that to frontend.
Frontend displays it.
That's an agent.
